## 1. 摘要与一页决策

### 1.1 项目一句话

> 构建一套**可控、可复现、可评测**的 AI 智能体语音合成能力：以开源基座 + 授权数据微调得到专属音色，并把「声音」抽象为一组**版本化、可单独调节、互不干扰的参数**，使同一音色能稳定地产出任意情绪、语速、语调、时长与场景的声音，且每次变更都经过回归门禁。

### 1.2 从需求到技术结论

| 原始需求（用户表述） | 技术翻译 | 本方案的应对 |
| --- | --- | --- |
| 「用来存储 AI 智能体声音训练的项目文件」 | 需要长期可维护的工程仓库，而非一次性脚本 | 第 10 章：目录规范、配置即代码、数据/模型版本管理、实验可追溯 |
| 「用什么东西来训练」 | 基座模型、训练框架、硬件、数据 | 第 4/6/7 章：双轨路线 + 数据流水线 + 训练三阶段 |
| 「技术路径走到哪儿、大概规划时间」 | 现状定位、阶段划分、里程碑与验收 | 第 11 章：现状 = Phase 0，三档排期（6–8 周 / 16–20 周 / 24–32 周） |
| 「高质量、保质量完成」 | 不只是「训出来」，而是「每次都稳定地好」 | 第 8 章：客观 + 主观双轨评估、固定回归集、CI 门禁、上线阈值表 |
| 「所有声音可以参数化细调」 | 核心差异化能力，需成体系设计 | 第 5 章：五层参数模型、控制手段映射、正交性与冲突消解、参数扫描验证 |

### 1.3 当前进度定位（诚实基线）

**技术路径当前位置：Phase 0（立项 / 选型核验期），尚未开始数据与训练。**

- 已完成：需求澄清（本文档）、方案骨架、参数化控制体系设计、评估门禁设计。
- 未完成：算力确认、数据授权与采集、基座模型联网核验与复现、任何训练产出、任何评测分数。
- 因此本文**不报告任何实测指标**；所有阈值均为「目标门禁」，需在 Phase 2 用基线实测校准。

### 1.4 一页决策建议（请评审时拍板）

| 编号 | 建议 | 理由 | 可推翻条件 |
| --- | --- | --- | --- |
| R1 | 采用**双轨路线**：开源基座做零样本/少样本克隆 + LoRA 微调做专属音色 | 兼顾快速出声与长期可控，避免单押一个模型 | 若 D5 允许云端商业 API，可用其做「质量上限对照」而非主线 |
| R2 | 基座选择把「**显式控制信号 + 时长可控 + 音色/情感解耦**」权重置于「纯自然度」之上 | 参数化细调是本项目第一需求，后补可控性成本极高 | 若 D4 不需要精确时长，可放宽到自然度优先 |
| R3 | 参数化能力**分层实现**，禁止全靠后处理 DSP | DSP 变速变调会损伤音质与说话人相似度；优先在模型条件层解决 | 无 |
| R4 | 评估体系与数据流水线**先于**训练落地 | 「保质量」依赖固定回归集与门禁，事后补等于没有 | 无 |
| R5 | 排期按**档 B（16–20 周，高质量可用）**作为基线承诺，档 A 仅作演示 | 高质量 + 全参数可控无法在 8 周内同时达标 | 若接受先上 MVP 再迭代，可改档 A 起步 |

## 2. 需求拆解与验收指标

### 2.1 功能性需求

| ID | 需求 | 优先级 | 验收方式 |
| --- | --- | --- | --- |
| F1 | 给定参考音频（或 speaker_id）合成目标音色语音 | P0 | 说话人相似度门禁 + 盲测 ABX |
| F2 | 中文合成，支持中英混、数字/日期/专名正确读法 | P0 | 发音回归集 CER / 人工听审 |
| F3 | 情感、语速、音高、能量、停顿可单独调节 | P0 | 参数扫描单调性测试 |
| F4 | 时长可精确控制（用于字幕/画面/口型对齐） | P1 | duration_mode=exact 误差门禁 |
| F5 | 任意参数组合可保存为 preset 并一键复现 | P0 | 同 preset 两次合成波形一致（固定 seed） |
| F6 | 流式输出，满足实时对话首包延迟 | P1 | P95 首包延迟压测 |
| F7 | 多说话人 / 多音色矩阵管理 | P2 | 音色注册表 + 权限隔离 |
| F8 | 训练产物版本化、可回滚、可审计 | P0 | 模型卡 + checkpoint manifest |

### 2.2 非功能性需求（「高质量保质量」的量化定义）

| ID | 维度 | 目标门禁（初版，Phase 2 校准） | 备注 |
| --- | --- | --- | --- |
| Q1 | 可懂度 | 中文 CER ≤ 3%（ASR 回环），英文 WER ≤ 5% | 固定 ASR 模型，避免自证 |
| Q2 | 说话人相似度 | ECAPA-TDNN cosine ≥ 0.82（vs 目标参考） | 同时要求不同说话人间 < 0.70 |
| Q3 | 自然度 | 主观 MOS ≥ 4.0 / 5，客观 UTMOS ≥ 3.8 | 两者需同时满足 |
| Q4 | 音质 | DNSMOS ≥ 3.2；无削波、爆音、拖尾、底噪 | 自动检测 + 听审 |
| Q5 | 情感可控 | 离散情感分类准确率 ≥ 85%，连续强度单调 ρ ≥ 0.9 | 见 8.4 参数扫描 |
| Q6 | 时长精度 | exact 模式误差 ≤ ±50ms 或 ±2%（取大者） | 仅当启用 F4 |
| Q7 | 实时性 | 流式首包 P95 ≤ 300ms；整句 RTF ≤ 0.3 | 指定硬件下测量 |
| Q8 | 稳定性 | 1000 句回归：0 crash、0 空音频、0 乱码、0 非静音异常 | 每次训练 CI 必跑 |
| Q9 | 可复现 | 同 (preset, 模型版本, seed, 文本) → 波形 byte-level 一致 | 固定推理栈与依赖锁 |
| Q10 | 参数正交 | 单参数扫描时，其他层指标漂移 ≤ 阈值（见 5.6） | 防「调语速把音色带跑」 |

### 2.3 明确不在 v0.1 范围内（防止范围蔓延）

- 歌唱合成、音乐生成、声音事件生成
- 实时语音转换（VC）/ 变声通话（与 TTS 是不同技术栈）
- 多语种全覆盖（v0.1 只承诺中文 + 中英混）
- 自研基础大模型（本项目定位为**基于开源基座的工程化与可控化**）

## 3. 总体技术架构

```
┌──────────────────────────────────────────────────────────────┐
│ L6 应用/接入层   Agent Runtime · SDK · REST/gRPC · WebSocket  │
├──────────────────────────────────────────────────────────────┤
│ L5 控制层 ★核心   VoiceSpec 解析 · 冲突消解 · Preset 版本化    │
│                  参数→条件映射 · 参数扫描器 · 权限/水印        │
├──────────────────────────────────────────────────────────────┤
│ L4 推理层         流式调度 · chunk 拼接 · adapter 热切换       │
│                  缓存 · 降级 · 并发/批处理                     │
├──────────────────────────────────────────────────────────────┤
│ L3 模型层         基座 TTS (零样本/指令) + LoRA/Adapter 组      │
│                  声码器 · 情感/时长控制头 · 水印注入            │
├──────────────────────────────────────────────────────────────┤
│ L2 训练层         SFT → 偏好对齐(DPO/RLAIF) → 蒸馏/量化        │
│                  实验跟踪 · checkpoint · 回归门禁 CI            │
├──────────────────────────────────────────────────────────────┤
│ L1 数据层         采集→清洗→对齐→标注→质检→版本化(DVC/LFS)     │
├──────────────────────────────────────────────────────────────┤
│ L0 基础设施       GPU · 对象存储 · 实验库 · 评测平台 · 审计日志 │
└──────────────────────────────────────────────────────────────┘
```

**分层原则**：L5 控制层是本项目的技术资产核心。模型可以换（L3），但参数契约（L5）必须稳定——这样未来替换基座时上层业务零改动。这是「长期可维护」的关键设计。

## 4. 候选模型对比与选型

### 4.1 候选清单（⚠️ 全部需联网核验版本 / 许可证 / 权重可得性）

| 候选 | 方向 / 特点 | 与「参数化细调」的契合度 | 主要风险 | 核验状态 |
| --- | --- | --- | --- | --- |
| CosyVoice 系列（CosyVoice 2 / 3）⚠️核验 | 零样本克隆 + 自然语言指令控制情感/方言/语速 + 流式 | **高**：指令即参数，易映射 StyleSpec | 指令自由度大 → 参数单调性难保证，需加约束解码 | ⚠️ |
| IndexTTS 系列（IndexTTS2）⚠️核验 | 主打**精确时长可控** + 音色/情感参考解耦 | **最高**（若需 F4）：时长与情感天然是两个独立输入 | 中文强、多语种待核验；社区规模与维护节奏待核验 | ⚠️ |
| Spark-TTS ⚠️核验 | 基于 LLM 的**属性级控制**（性别/音高/语速等粗+细粒度属性） | **最高**：属性本身就是参数 schema | 属性覆盖有限，细粒度情感/场景需自建映射 | ⚠️ |
| Fish-Speech / OpenAudio S1 ⚠️核验 | 多语种、标记/emoji 控制情感、dual-AR | 中高：风格标记易做参数化 | 可控维度偏「离散标签」，连续细调需扩展 | ⚠️ |
| F5-TTS ⚠️核验 | Flow-matching + DiT，零样本克隆，推理快 | 中：自然度/效率好，可控性需二次开发 | 原生控制面窄 | ⚠️ |
| GPT-SoVITS ⚠️核验 | 少样本微调，社区成熟，小数据音色定制 | 中低：音色定制好用，**可控性弱** | 适合作为「微调轨」备选，不适合当控制面 | ⚠️ |
| Seed-TTS / Qwen3-TTS 类 ⚠️核验 | 论文级 ICL/指令能力 | 视开源情况 | **权重可得性与商用许可最不确定** | ⚠️ |
| VoxCPM / 其他 2025–2026 新基座 ⚠️核验 | 端到端、小参数量 | 待评估 | 版本漂移快 | ⚠️ |
| 声码器：HiFi-GAN / BigVGAN / Vocos ⚠️核验 | 波形重建 | 影响 Q4 | 与基座耦合，一般不单独替换 | ⚠️ |

> 说明：以上为**方向性候选池**，不是排名。最终名次必须在 Phase 2 用同一份固定回归集、同一硬件、同一套指标实测后产生，禁止凭印象定选型。

| 维度 | 权重 | 说明 |

### 4.3 推荐：双轨路线（R1）

```
轨道 A · 基座轨（负责「控制面」）
  选一个原生支持显式控制信号 + 时长可控 + 音色/情感解耦的开源基座
  → 输出：零样本/少样本即可用，参数通过 L5 映射到原生条件
  → 优先候选：IndexTTS2 / Spark-TTS / CosyVoice 系（Phase 2 实测定型）

轨道 B · 定制轨（负责「音色资产」）
  在 A 之上（或并行用 GPT-SoVITS 类）做 LoRA / Adapter 微调
  → 输出：专属音色的 speaker adapter，可热插拔、可加权混合
  → 数据门槛见 6.3

汇合点：L5 VoiceSpec
  无论走哪条轨，对上层暴露同一套参数契约
```

**为什么不全押一个模型**：控制能力强的模型未必音色定制最省数据；微调成熟的方案未必可控性强。用 L5 契约把两者解耦，是本项目最重要的架构决策。

### 4.4 训练框架与工具栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 深度学习框架 | PyTorch 2.x + CUDA | 生态与开源 TTS 事实标准 |
| 分布式 / 混合精度 | DeepSpeed 或 FSDP + bf16 | 单卡起步，可扩展到多卡 |
| 参数高效微调 | PEFT / LoRA（+ 可选 QLoRA） | 多 adapter 共存、可插值、回滚成本低 |
| 实验跟踪 | MLflow（自托管）或 W&B | 超参 / 指标 / 产物可追溯，满足 F8 |
| 数据版本 | DVC + 对象存储（或 git-lfs 起步） | 数据集可复现，回归集不可被悄悄改动 |
| 模型注册 | MLflow Model Registry + 模型卡 | checkpoint → 门禁 → 上线 全链路 |
| 评测 | 自建 Eval Harness（见第 8 章） | 统一指标实现，避免各人各算 |
| 服务化 | FastAPI / gRPC + Triton 或 vLLM 类推理栈（TTS 适配需评估） | 流式与并发 |
| 依赖锁定 | conda / uv + lock 文件 + Docker | 满足 Q9 byte-level 可复现 |

## 5. 参数化细调体系（核心章节）

### 5.1 设计目标

1. **完备**：声音的所有可感知维度都有参数（不是只给「语速/音调」两个旋钮）。
2. **正交**：调 A 不应悄悄改变 B（否则「细调」变成「调一堆补偿参数」）。
3. **单调**：参数增大，感知量按预期方向单调变化，可预测。
4. **可复现**：preset = 参数集 + 模型版本 + seed + 依赖锁，任意时刻可重放。
5. **可实现**：每个参数明确标注由哪一层实现，不画大饼。

### 5.2 五层参数模型

```
VoiceSpec
├── L-A 身份层 IdentitySpec    「是谁在说」    —— 变化最慢，需授权
├── L-B 韵律层 ProsodySpec     「怎么说」      —— 连续量，细调主战场
├── L-C 风格层 StyleSpec       「什么状态说」  —— 离散+连续+自然语言
├── L-D 语言层 LinguisticSpec  「把字念对」    —— 确定性规则，零容忍错误
└── L-E 渲染层 RenderSpec      「最后怎么送出去」—— 工程参数，可后处理
```

### 5.3 参数总表

#### L-A 身份层 `IdentitySpec`

| 参数 | 类型 | 取值 / 默认 | 说明 | 实现层 |
| --- | --- | --- | --- | --- |
| `speaker_id` | string | 必填 | 注册音色 ID，指向 speaker adapter 或 embedding | L5→L3 |
| `ref_audio_uri` | uri | 可选 | 零样本参考音频（对象存储路径，禁止内联二进制） | L3 条件 |
| `ref_text` | string | 与 ref_audio 配对 | 参考音频转写，提升克隆稳定性 | L3 条件 |
| `speaker_lock` | bool | `true` | 锁定音色，禁止风格/情感参数带偏说话人 | L5 约束 + 相似度门禁 |
| `voice_blend` | list[{speaker_id, weight}] | 可选 | 多音色插值（adapter 加权 / embedding 插值） | L3 adapter 混合 |

#### L-B 韵律层 `ProsodySpec`（连续细调主战场）

| 参数 | 类型 | 范围 / 默认 | 感知量 | 实现层 | 风险 |
| --- | --- | --- | --- | --- | --- |
| `pitch_semitones` | float | `[-12, 12]` / `0` | 整体音高 | 优先：声学特征 F0 偏移（decoder 前）；**禁用**波形变调 | 大幅偏移损相似度 |
| `pitch_range` | float | `[0.5, 2.0]` / `1.0` | 语调起伏幅度 | F0 contour 缩放 | 过大会「唱起来」 |
| `pitch_contour` | enum / curve[] | `native\|flat\|expressive` 或归一化 F0 曲线 | 逐字/逐音节语调 | 强制对齐后注入 F0 曲线 | 需模型支持显式特征输入 |
| `energy_db` | float | `[-6, 6]` / `0` | 音量/力度感 | energy contour 缩放 + 后级增益 | 与 loudness 归一化冲突 |
| `rate` | float | `[0.5, 2.0]` / `1.0` | 全局语速 | 时长预测器 / token 数缩放 | **与 duration_* 互斥** |
| `duration_mode` | enum | `free\|exact\|range` / `free` | 时长策略 | 时长可控头（IndexTTS2 类） | 基座不支持则降级为后处理并标记 |
| `duration_ms` | int | 与 exact 配对 | 目标总时长 | 同上 | 过短会吞字 |
| `duration_ratio` | float | `[0.7, 1.5]` | 相对基准时长 | 同上 | — |
| `pause_profile` | enum/preset | `default\|news\|story\|gentle` | 停顿分布 | 文本侧 break 标记 + 时长模型 | — |
| `pauses` | list[{after_char_index, ms}] | 可选 | 精确插入停顿 | SSML-like `[[break:300]]` | 与 duration 精确模式叠加需校验 |
| `intonation_strength` | float | `[0, 1]` / `0.6` | 疑问/强调的语调夸张度 | F0/energy 联合调制 | — |

#### L-C 风格层 `StyleSpec`

| 参数 | 类型 | 取值 / 默认 | 说明 | 实现层 |
| --- | --- | --- | --- | --- |
| `emotion` | enum | `neutral\|happy\|sad\|angry\|fear\|surprise\|tender\|professional\|...` / `neutral` | 离散情感 | 情感 token / 情感参考音频 / 属性条件 |
| `emotion_strength` | float | `[0, 1]` / `0.7` | 情感强度（连续细调） | 条件向量插值，需验证单调性 |
| `emotion_ref_uri` | uri | 可选 | 独立情感参考（与音色参考解耦） | L3 双参考输入 |
| `style_prompt` | string | 可选 | 自然语言指令（「疲惫地、压低声音、慢慢说」） | 指令微调基座（CosyVoice 类） |
| `scenario` | enum | `播报\|客服\|陪伴\|讲故事\|车载\|ASMR\|教学` | 场景预设（内部展开为一组 L-B/L-C 默认值） | L5 preset 展开 |
| `formality` | float | `[0, 1]` / `0.5` | 正式↔随意 | 风格 adapter 插值 / 指令 |
| `style_adapter_mix` | list[{name, weight}] | 可选 | 多个风格 LoRA 加权混合 | L3 adapter 混合 |

> **设计要点**：`emotion` 与 `style_prompt` 同时给出时以 `emotion` 为准（离散优先，保证可复现），`style_prompt` 仅作为补充修饰并写入审计日志。自然语言指令不可完全复现，因此**不允许单独作为 preset 的唯一控制手段**。

#### L-D 语言层 `LinguisticSpec`（零容忍）

| 参数 | 类型 | 说明 | 实现层 |
| --- | --- | --- | --- |
| `lang` | enum | `zh\|en\|zh-en-mix` | 前端文本归一化 |
| `text_normalize` | bool / rules | 数字、日期、货币、单位、缩写读法 | TN 前端（规则 + 可覆盖） |
| `pronunciation_dict` | map[string→phoneme] | 多音字、专名、品牌、地名覆盖 | G2P 后覆写，最高优先级 |
| `phoneme_overrides` | list[{span, phonemes}] | 句内局部音素强制 | 同上 |
| `code_switch_policy` | enum | `auto\|keep_original\|transliterate` | 中英混处理 |
| `emphasis` | list[{span, weight[-1,1]}] | 局部重读（负值为弱化） | F0/energy/duration 联合局部调制 |
| `prosody_marks` | list | 边界/短语层级标注（#1 #2 #3） | 韵律层级预测 |

> L-D 属于**确定性规则层**：任何发音错误都算 bug，不进「风格调优」范畴，必须进回归集。

#### L-E 渲染层 `RenderSpec`

| 参数 | 类型 | 默认 | 说明 | 实现层 |
| --- | --- | --- | --- | --- |
| `sample_rate` | int | 24000 / 48000（随基座） | 采样率 | 声码器 |
| `format` | enum | `wav\|pcm_s16le\|opus\|mp3` | 交付格式 | 后处理 |
| `loudness_lufs` | float | `-16`（对话）/ `-14`（播报） | 响度归一化 | EBU R128 后处理 |
| `peak_limit_dbtp` | float | `-1.0` | 防削波 | limiter |
| `denoise` / `dereverb` | bool | `false` | 一般不需要（合成音频本就干净），仅用于参考音频清洗链路 | 数据侧 |
| `post_reverb` | preset | `none` | 场景空间感 | 后处理（可选） |
| `seed` | int | 固定 | 采样随机性 | 全链路 |
| `streaming` / `chunk_ms` | bool/int | `false` / `200` | 流式分块 | L4 |
| `watermark` | bool | `true` | 合成音频水印 | L3/L4 注入 |

### 5.4 控制手段映射（每个参数「靠什么实现」）

| 手段 | 覆盖参数 | 优点 | 代价 / 禁忌 |
| --- | --- | --- | --- |
| **M1 原生条件注入**（属性 token / 指令 / 情感 token / 时长头） | emotion, rate, duration, pitch 粗粒度 | 音质最好、与说话人解耦最干净 | 依赖基座能力；维度有限 → 需 Phase 2 探测基座实际支持哪些 |
| **M2 声学特征编辑**（decoder 前改 F0 / energy / duration contour） | pitch_*, energy_db, intonation, emphasis, pauses | 连续细调最精确，无 DSP 伪影 | 需基座暴露中间特征；改动侵入模型，需维护 patch |
| **M3 Adapter / LoRA 加权混合** | voice_blend, style_adapter_mix, formality, scenario | 风格可插值、可热插拔、可回滚 | 多 adapter 共存显存开销；混合权重需验证不产生怪声 |
| **M4 文本侧标记**（SSML-like break / phoneme / emphasis） | pauses, phoneme_overrides, emphasis, TN | 完全确定性、可复现、跨模型通用 | 只覆盖能写进文本的部分 |
| **M5 参考音频解耦**（音色 ref + 情感 ref 分离） | emotion_ref, speaker ref | 零训练即可获得细腻风格 | 参考音频质量直接影响结果；需入库质检 |
| **M6 后处理 DSP** | loudness, peak, format, reverb, 采样率 | 与模型无关，稳定 | **禁止用于 pitch / rate 主控制**（会产生金属音、损伤相似度）；仅作为降级路径并标记 |

**优先级规则**：`M4（确定性规则）> M1（原生条件）> M2（特征编辑）> M5（参考）> M3（adapter）> M6（DSP）`。当同一物理量有多个来源时，按此优先级取一，其余丢弃并记 warning。

### 5.5 参数冲突消解矩阵

| 冲突对 | 规则 |
| --- | --- |
| `rate` ↔ `duration_mode=exact/range` | **互斥**，同时给出直接报错 400（不是静默覆盖） |
| `duration_ms` ↔ `pauses[]` | 允许，但校验 `Σpauses < duration_ms × 0.4`，超出报错 |
| `energy_db` ↔ `loudness_lufs` | 两者作用不同（前者是表现力、后者是交付响度），同时生效；loudness 最后做 |
| `emotion` ↔ `style_prompt` | 离散优先；style_prompt 作为修饰，写审计日志 |
| `pitch_semitones` ↔ `pitch_contour` | contour 为相对形状，semitones 为全局偏移，叠加生效 |
| `scenario` ↔ 显式 L-B/L-C 参数 | 显式值覆盖 scenario 展开的默认值（preset 是「默认值集合」，不是强制值） |
| `voice_blend` ↔ `speaker_lock=true` | 禁止 blend（锁定时只允许单一音色） |

> **设计原则**：冲突一律**显式报错或显式优先级**，绝不静默。静默覆盖是「参数化细调」最常见的可信度杀手。

### 5.6 正交性与单调性验证（保「细调」不变成「乱调」）

对每一个连续参数执行**单参数扫描**：固定其余参数与 seed，取 5 个值（含默认），合成同一组 20 条固定文本，检查：

| 检查项 | 通过条件 |
| --- | --- |
| 感知单调性 | 目标感知量（如语速、F0 中位数、情感强度分类得分）与参数值 Spearman ρ ≥ 0.90 |
| 音质不崩 | 各点 UTMOS 相对默认值下降 ≤ 0.30，DNSMOS ≥ 3.2 |
| 说话人不漂移 | ECAPA cosine 相对参考变化 ≤ 0.03（对应 Q10） |
| 可懂度不退化 | CER 相对默认值上升 ≤ 1 个百分点 |
| 无突变 | 相邻档位间无「风格跳变」，由 3 人听审确认 |

不通过的参数**不得开放给业务**，降级为「内部实验参数」或改为离散档位。这项测试是 F3 的正式验收方法，也是 v0.1 相对普通 TTS 方案的主要增量。

### 5.7 Preset 版本化与可复现

```yaml
# presets/warm_companion_v1.yaml
preset_id: warm_companion
version: 1.3.0
model:
  base: <base-model-id>@<commit>
  adapters: [{name: gentle_lora, weight: 0.8}]
  deps_lock: locks/infer-2026-11.lock
identity: {speaker_id: agent_main, speaker_lock: true}
prosody:  {rate: 0.92, pitch_semitones: -0.5, pitch_range: 0.95,
           intonation_strength: 0.55, pause_profile: gentle}
style:    {emotion: tender, emotion_strength: 0.6, scenario: 陪伴,
           formality: 0.25}
linguistic:{lang: zh, text_normalize: true, pronunciation_dict: dicts/brand_v2}
render:   {sample_rate: 48000, loudness_lufs: -16, seed: 20261104,
           watermark: true, format: opus}
audit:    {created_by: ..., approved_by: ..., golden_set_passed: gs-2026-11-a}
```

- preset 变更走 PR + 回归门禁，禁止线上直接改 JSON。
- 每次合成日志落 `(preset_id@version, model@commit, seed, text_hash, 输出 hash)`，满足 Q9 与审计。
- 回归集（golden set）与 preset 绑定：preset 升级必须重跑全量门禁。

## 6. 数据工程

> 「高质量」的上限由数据决定，不由模型决定。本章是投入重点。

### 6.1 数据流水线

```
① 采集/授权 → ② 预处理 → ③ 质检门禁 → ④ 转写与对齐 → ⑤ 标注
   → ⑥ 切片与打包 → ⑦ 版本冻结 → ⑧ 划分(训练/验证/回归/golden)
```

| 步骤 | 工具 / 方法（⚠️版本待核验） | 产出 | 关键控制点 |
| --- | --- | --- | --- |
| ① 采集 | 录音棚 / 授权素材 / 自建录制 | 原始 wav（≥48kHz/24bit 存档） | **授权书先行**（见第 14 章） |
| ② 预处理 | VAD、降噪、去混响、人声分离、说话人日志(diarization)、响度归一 | 干净单说话人片段 | 禁止过度降噪造成「电音」；保留原始档 |
| ③ 质检 | SNR、削波率、静音比、DNSMOS/PESQ、时长分布、ASR 置信度 | 质量分 + 通过/拒绝 | **逐条打分，不通过不进训练集** |
| ④ 转写对齐 | ASR（Whisper / Paraformer 类）→ 人工校验 → 强制对齐（MFA / WhisperX 类）→ G2P | text + 音素 + 字级时间戳 | 时间戳是 M2 特征编辑与 F4 时长控制的前提 |
| ⑤ 标注 | 情感、场景、语速档、语气、重读、发音例外 | 结构化 label | 双人标注 + 一致性检验（Cohen κ ≥ 0.7） |
| ⑥ 切片 | 按句/按静音切 3–15s，去头尾静音 | 训练样本 | 避免过长导致显存与注意力退化 |
| ⑦ 冻结 | DVC / git-lfs + manifest（hash、来源、授权 ID、质检分） | 数据集版本 `ds-YYYYMMDD-x` | 回归集单独冻结，任何人不可改 |
| ⑧ 划分 | train / val / test / **golden_set** | 四份不相交 | 按说话人 + 按文本去重，防泄漏 |

### 6.2 质检门禁阈值（初版）

| 指标 | 阈值 | 处置 |
| --- | --- | --- |
| 有效时长 | 2–15 s | 超出切片或丢弃 |
| SNR | ≥ 25 dB | 降噪重跑，仍不达标丢弃 |
| 削波样本比例 | 0 | 丢弃 |
| 非静音占比 | 40%–95% | 重切 |
| DNSMOS | ≥ 3.3 | 低于则丢弃或重录 |
| ASR 转写置信 / 人工校验 CER | = 0（人工确认） | 必校，禁止未校验转写入训 |
| 说话人一致（diarization） | 单说话人概率 ≥ 0.98 | 丢弃 |
| 字级对齐误差 | ≤ 30 ms | 重对齐 |

### 6.3 数据量门槛（按路线）

| 路线 | 数据量 | 预期效果 | 备注 |
| --- | --- | --- | --- |
| 零样本克隆 | 3–10 s 参考音频 | 可用，相似度中等 | 参考音频质量决定上限 |
| 少样本 / 提示学习 | 1–5 min | 相似度明显提升 | 靠 ICL，不训练 |
| LoRA 音色微调 | 10–60 min 高质量单说话人 | 稳定专属音色（推荐起点） | 数据质量 >> 数量 |
| 风格 / 情感适配 | 每风格 ≥ 30 min 带标注 | 情感可控 | 需覆盖 8 类情感 |
| 全量 SFT / 高保真定制 | 5–20 h | 接近录音棚级 | 成本高，仅在档 C 考虑 |

> **关键判断**：先用 10–60 min 精标数据 + LoRA 打通全链路，再决定是否扩到小时级。不要一上来就录 20 小时。

### 6.4 公开数据集用途（⚠️许可证与用途需核验）

| 数据集 | 用途 | 注意 |
| --- | --- | --- |
| LibriTTS / VCTK 类 | 英文能力对照、流水线自测 | 不可用作商业音色 |
| AISHELL-3 / WenetSpeech 类 | 中文多说话人基座验证 | 许可证与商用范围需逐项核验 |
| ESD / CASIA / EmoV-DB 类 | 情感标注体系与情感分类器训练 | 多为研究用途 |
| Common Voice 类 | 多语种扩展储备 | 版本与许可核验 |

**原则**：公开数据用于「流水线验证 / 评测对照 / 通用能力」，**专属音色的训练数据必须自有授权**，二者物理隔离（不同目录、不同 manifest 字段）。

## 7. 训练方案

### 7.1 硬件基线（三档，供 D6 决策）

| 档 | 配置 | 适用 | 约束 |
| --- | --- | --- | --- |
| H-1 起步 | 1× 24GB GPU（3090/4090/A10 级） | Phase 0–3，LoRA、推理、评测 | 无法做全量 SFT / 大 batch |
| H-2 推荐 | 1× 80GB（A100/H100）或 4–8× 24GB | 档 B 全流程，含偏好对齐 | 成本与排期平衡点 |
| H-3 规模化 | 8× 80GB + 高速互联 + 对象存储 | 档 C、全量 SFT、多音色矩阵 | 仅在有明确规模需求时上 |

**存储**：原始音频 + 中间产物 + checkpoint，按 1–5 TB 起步规划（随数据量与 checkpoint 保留策略变化）。

### 7.2 三阶段训练

```
Stage 1 · SFT / 适配
  基座权重冻结或半冻结 → LoRA 注入 → 授权数据微调
  目标：说话人相似度、可懂度达标（Q1/Q2）
  产出：speaker adapter v1 + 模型卡 + 首次全量门禁报告

Stage 2 · 偏好对齐（DPO / RLAIF）
  用自动代理奖励构造偏好对：
    reward = w1·UTMOS + w2·说话人相似度 + w3·(1 - CER) + w4·情感/时长符合度
  同一文本多采样 → 打分 → 构造 (chosen, rejected) → DPO
  目标：自然度与「参数遵循度」提升（Q3 + F3/F4）
  风险：奖励黑客（reward hacking）→ 必须保留人评盲测作为最终裁判

Stage 3 · 蒸馏 / 量化 / 部署化
  FP16/bf16 → INT8/INT4（若支持）· 流式 chunk 适配 · 热加载
  目标：Q7 延迟与成本，且不越过 Q1–Q4 门禁
  ⚠️ 量化后必须重跑全量门禁，任何指标越界即回滚
```

### 7.3 训练工程规范

- **超参**：全部写进 `configs/` YAML，禁止散落在脚本里；每次运行记录完整 config hash。
- **checkpoint**：按 `step` + `门禁分数` 双命名；只保留 Top-K（按 Q1–Q4 综合分）+ 最近 3 个，其余归档。
- **早停**：以 val 集 UTMOS + 相似度为主，CER 为硬约束（CER 恶化即停）。
- **防退化**：
  - 冻结底层 / 低 LR 防灾难性遗忘；
  - 保留通用语料 replay（比例 10–20%）防口齿与 multilingual 能力退化；
  - 监控「静音/吞字/复读」专项集（100 条难例）；
  - 每个 checkpoint 跑固定发音回归集（多音字、中英混、长数字）。
- **实验跟踪**：每次运行必须关联 `dataset@version + code@commit + config@hash + 门禁报告`，否则结果不采纳。
- **可复现**：锁 CUDA / cuDNN / torch 版本与随机种子，Docker 化训练镜像。

### 7.4 训练不做的事

- 不从头预训练基础模型（成本与数据均不匹配项目定位）。
- 不用未授权/来源不明音频。
- 不在没有门禁的情况下「看感觉挑 checkpoint」。

## 8. 质量保障与评估体系

> 「保质量」= **固定标准 + 自动门禁 + 人工盲测 + 每次变更都回归**。

### 8.1 四套数据集，职责分离

| 集合 | 规模（初版） | 用途 | 可改性 |
| --- | --- | --- | --- |
| train | 主体 | 训练 | 版本化可增 |
| val | ~200 条 | 训练中早停 | 冻结 |
| test | ~300 条 | 版本间对比 | 冻结 |
| **golden_set** | ~100 条 + 100 条难例 | **上线门禁 / 回归 / 参数扫描** | **绝对冻结，PR 禁止修改** |

golden_set 覆盖：8 类情感 × 3 种语速 × 中英混 × 多音字 × 长数字/日期 × 专名 × 极短句 × 极长句 × 疑问/感叹 × 停顿密集文本。

### 8.2 客观指标

| 指标 | 方法 | 门禁 |
| --- | --- | --- |
| CER / WER | 固定 ASR 回环（Whisper / Paraformer 类），ASR 模型版本锁定 | Q1 |
| 说话人相似度 | ECAPA-TDNN embedding cosine | Q2 |
| 自然度（代理） | UTMOS / SpeechBERTScore 类 | Q3 辅助 |
| 音质 | DNSMOS / PESQ、削波检测、静音异常检测 | Q4 |
| 韵律 | F0 RMSE、duration MAE、energy corr | 参数扫描用 |
| 情感符合度 | 固定情感分类器 top-1 + 人评抽样 | Q5 |
| 时长 | 实测音频时长 vs 目标 | Q6 |
| 性能 | 首包延迟、RTF、显存峰值、并发 QPS | Q7 |

> **反自证原则**：ASR / 相似度 / MOS 代理模型的版本必须锁定并写进模型卡；不得用被评测模型自身的组件做裁判。

### 8.3 主观评测规范

| 项 | 规范 |
| --- | --- |
| 方法 | 自然度 MOS / 对比 CMOS / 相似度 ABX / 情感 MUSHRA |
| 评审 | ≥ 20 人，听力正常，先过筛选测试（含锚点） |
| 样本 | ≥ 40 条/轮，随机序、盲测、含隐藏锚点与重复项测一致性 |
| 统计 | 报均值 + 95% 置信区间；CMOS 差值需 CI 不跨 0 才判定胜出 |
| 频率 | Stage 1/2/3 各一轮；上线前一轮；此后每季度或每次模型升级 |
| 记录 | 原始评分表归档，禁止只留平均分 |

### 8.4 CI 门禁流程

```
任意变更（数据 / 代码 / 超参 / checkpoint / preset / 依赖）
   → 自动触发 golden_set 全量合成
   → 客观指标计算 → 与 Q1–Q10 逐项比对
   → 参数扫描（连续参数 5 点）
   → 生成门禁报告（含波形样本、频谱、失败项明细）
   → 任一硬指标不通过 → 阻断，禁止进入人工评测
   → 硬指标通过 → 进入主观盲测（仅重大版本）
   → 通过 → 模型注册为 candidate → 人工批准 → production
```

硬指标（阻断项）：Q1、Q2、Q4、Q8、Q9、Q10、F4 时长精度。
软指标（需评审）：Q3、Q5、Q7。

### 8.5 上线门禁速查表

| 类别 | 指标 | 阈值 | 类型 |
| --- | --- | --- | --- |
| 可懂度 | CER | ≤ 3% | 硬 |
| 相似度 | ECAPA cosine | ≥ 0.82 | 硬 |
| 音质 | DNSMOS | ≥ 3.2，无削波 | 硬 |
| 复现 | 波形一致性 | byte-level 一致 | 硬 |
| 稳定 | 1000 句 | 0 异常 | 硬 |
| 正交 | 单参数漂移 | ≤ 0.03 cosine | 硬 |
| 自然度 | MOS | ≥ 4.0 | 软（盲测） |
| 自然度 | UTMOS | ≥ 3.8 | 软 |
| 情感 | 分类准确率 | ≥ 85% | 软 |
| 参数 | 单调 ρ | ≥ 0.90 | 软→硬（F3 验收后转硬） |
| 延迟 | 首包 P95 | ≤ 300ms | 软（按场景） |

> 所有阈值在 Phase 2 用基线实测后校准一次，校准结果写入 v0.2；校准只能**收紧**，如需放宽必须书面说明理由并经评审。

## 9. 推理服务与工程实现

### 9.1 API 契约（草案）

```
POST /v1/synthesize
{
  "text": "……",
  "preset": "warm_companion@1.3.0",     // 与 inline spec 二选一
  "spec": { ...VoiceSpec 覆盖项... },   // 覆盖 preset 的显式参数
  "stream": true,
  "request_id": "..."
}
→ 200  audio/opus 流  或  { audio_uri, duration_ms, audit_id, model_version }

GET  /v1/voices                 // 音色注册表
GET  /v1/presets               // preset 列表与版本
POST /v1/presets/validate      // 冲突消解预检（不合成）
GET  /v1/eval/reports/{id}     // 门禁报告
```

**设计要点**：
- `preset` 与 `spec` 合并规则 = preset 为默认值集合，spec 显式覆盖；冲突按 5.5 处理并返回 warnings。
- `request_id` 全链路透传，日志关联 `preset@version + model@commit + seed + text_hash + audio_hash`。
- 提供 `validate` 接口让业务侧在合成前发现互斥参数，避免 400 出现在生产。

### 9.2 流式与延迟预算

| 环节 | 预算（目标） |
| --- | --- |
| 文本归一化 + preset 解析 + 冲突校验 | ≤ 10 ms |
| 首 chunk 声学/token 生成 | ≤ 180 ms |
| 声码器 + 编码 + 首包发出 | ≤ 80 ms |
| 首包 P95 合计 | ≤ 300 ms |
| 后续 chunk | 节奏稳定，无累计漂移 |

工程要点：chunk 边界处的韵律连续性（避免拼接处 F0 跳变）、跨 chunk 的 duration 预算全局分配（保证 exact 时长在流式下仍成立）、预热与 adapter 常驻显存、批量/并发队列隔离实时与离线任务。

### 9.3 降级与监控

- 降级链：`原生时长控制 → 特征编辑 → DSP（标记 degraded=true 并告警）`。
- 监控：QPS、首包/整句延迟、CER 抽样、静音/异常率、显存、门禁分数趋势（模型漂移）。
- 回滚：模型注册表保留上一 production 版本，一键切回；preset 版本可单独回滚。
- 审计：每次合成留痕，水印默认开启（见第 14 章）。

## 14. 合规、安全与伦理

1. **声音授权**：每个 speaker 必须有书面授权，明确用途、期限、地域、可撤销条款；manifest 记录 `license_id` 与授权文件 hash。
2. **可追溯水印**：默认开启合成音频水印（AudioSeal 类方案 ⚠️核验），保留合成日志，支持事后溯源与鉴伪。
3. **克隆权限**：`ref_audio_uri` 上传需鉴权；音色注册走审批；禁止任意用户上传他人音频即克隆。
4. **个人信息**：原始录音按个人信息/生物识别信息级别管理，加密存储、访问审计、最小权限、到期删除。
5. **许可证合规**：P0 逐个核验基座、声码器、数据集、评测模型的 LICENSE；商业用途不可用的候选直接剔除（4.2 一票否决）。
6. **输出标识**：对外交付的音频/接口明确标注「AI 合成」，避免误导。
7. **审计日志**：`request_id → preset@version → model@commit → seed → text_hash → audio_hash → watermark_id` 全链路留存。

| **D3** | 声音数量：1 个主音色 vs 多音色矩阵 | 4、7、10、11 | 决定 adapter 架构与是否走档 C |
| **D4** | 是否需要**精确时长控制**（配音/字幕/口型对齐） | 4.1、F4、Q6 | 直接决定基座能不能选、IndexTTS2 类是否必选 |
| **D5** | 是否允许云端商业 TTS API（做质量上限对照 / 兜底） | 4、12 | 影响是否需要完全自建 |
| **D6** | 算力预算与硬件（H-1/H-2/H-3） | 7、11、12 | 决定档 B 是否可承诺 |
| **D7** | 商用许可要求（是否必须可商用、是否接受 AGPL） | 4.2、14 | 一票否决项，P0 必做 |
| **D8** | 语言范围（仅中文 / 中英混 / 多语种） | 2.3、6、L-D | 决定数据与评测集规模 |
| **D9** | 情感粒度：离散 8 类 / 连续向量 / 自然语言指令 / 三者都要 | 5.3 L-C | 决定参数体系与基座能力要求 |
| **D10** | 交付形态：本地权重 / 私有 API 服务 / SDK / 一体机 | 9、10、11 | 决定服务化与部署工作量 |

## 附录 C：VoiceSpec 参数配置示例

### C.1 实时陪伴场景（温柔、稍慢、低音）

```json
{
  "preset": "warm_companion@1.3.0",
  "spec": {
    "identity": {"speaker_id": "agent_main", "speaker_lock": true},
    "prosody": {"rate": 0.92, "pitch_semitones": -0.5, "pause_profile": "gentle"},
    "style": {"emotion": "tender", "emotion_strength": 0.6, "scenario": "陪伴"},
    "linguistic": {"lang": "zh", "pronunciation_dict": "dicts/brand_v2"},
    "render": {"streaming": true, "chunk_ms": 200, "loudness_lufs": -16}
  }
}
```

### C.2 字幕对齐场景（精确时长 3.2 秒）

```json
{
  "preset": "news_anchor@2.0.0",
  "spec": {
    "prosody": {
      "duration_mode": "exact", "duration_ms": 3200,
      "pause_profile": "news"
    },
    "style": {"emotion": "professional", "emotion_strength": 0.3},
    "render": {"streaming": false, "loudness_lufs": -14, "seed": 42}
  }
}
```
> 注意：此处**不能**同时给 `rate`，否则按 5.5 返回 400 互斥错误。
