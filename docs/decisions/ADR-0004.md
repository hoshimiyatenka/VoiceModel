## 1. 背景

用户第四轮要求：「v0.4 尽量把文档写全一点 再迭代几个版本就可以落地实施了」。

v0.3 已把参数化控制层从文字约定固化为机器可执行契约（VoiceSpec JSON Schema 2020-12 + 错误码表 + 校验脚本 + CI），但**仓库仍没有任何训练 / 控制 / 服务的实现代码**，且全项目处于 Phase 0：无算力、无数据、无数据授权、无法务签字、任何实测指标。

此时存在两条路：

- **路线甲**：为了让仓库「看起来能跑」，现在就写训练循环、控制层实现、API 服务。
- **路线乙**：先把「怎么做」写成可照抄的实施规格、配置模板、模块签名与 CI 校验，实现留到 Phase 2/3 有真实条件后再填。

## 2. 决策

**采用路线乙**。v0.4 交付物限定为四类：

1. **实施规格**（`docs/implement/**` 九份）：函数签名、字段 schema、端点、判定逻辑、单测组织、门禁流程、法务清单。
2. **配置模板**（`configs/presets/` `configs/train/` `configs/base/`）：全部标 `status: template` / `# 模板 / Phase 0 / 非实测`，数值用 `<...>` 占位或明确「目标值 / 待校准」。
3. **代码骨架**（`src/**`）：只定模块边界与函数签名，函数体一律 `raise NotImplementedError("Phase 3 实现：见 ...")`。
4. **一致性守卫**（`scripts/check_consistency.py` + `tests/unit/test_spec_consistency.py`）：把契约常量、错误码唯一性、校准状态、相对链接、模板状态标记变成可跑断言。

**契约冻结**：VoiceSpec 保持 `spec_version="0.3.0"`，v0.4 **不改 schema、不升版本、无 BREAKING CHANGE**（主方案 §7.1）。

**版本收敛**（D22）：v0.4 规格全量 → v0.5 评审回填 + D 拍板 + 法务清单 → v1.0 冻结 → 档 B 实施。硬前置门 G0 未过不进 P1（主方案 §3.3 / §14.3）。

## 3. 理由（不可丢）

| # | 理由 |
| --- | --- |
| 1 | **Phase 0 无真实条件**：没有数据授权（D1）、没有算力（D6）、没有法务签字（D11）、没有 baseline 分数。此时写的「实现」无法运行、无法验证，只会制造假进度。 |
| 2 | **避免与未来实测结论冲突**：实现里若写死基座、超参、capability flags，Phase 2 同台实测后大概率要推翻；先定规格与签名，实测结果回填配置即可。 |
| 3 | **规格先行能把「写全」变成可验证的事**：编号闭合、追溯矩阵、单一真源、CI 守卫都是机器可查的；单纯堆章节不可查。 |
| 4 | **契约是最高变更成本项**：schema 改动须 major 升级 + golden_set 全量回归 + 错误码表同步。冻结它可让 v0.5/v1.0 的迭代集中在评审与法务，不反复动根基。 |
| 5 | **防四类漂移**（R-19 规格↔骨架、R-20 错误码↔实现、R-21 模板当 production、R-22 目标值当实测）：先立守卫，后填实现，比实现完再补便宜得多。 |
| 6 | **用户目标可判定**：「再迭代几个版本就可以落地实施」需要一个终点；G0 + v1.0 冻结给出可判定的准入，避免无限迭代。 |

## 4. 备选与否决

| 备选 | 结论 | 理由 |
| --- | --- | --- |
| 路线甲：现在写实现代码 | **否决** | 无数据 / 算力 / 授权 / 法务，实现不可验证；会与 Phase 2 实测结论冲突；制造假进度 |
| 只补文档不落模板 / 骨架 / CI | **否决** | 「写全」不可验证；无法挡住 R-19–R-24 漂移；v0.5 仍需重做 |
| 现在升 VoiceSpec 到 1.0.0 以「一次到位」 | **否决** | 无实测依据的 major 升级会迫使 golden_set 全量回归，而 golden_set 实体尚不存在 |
| 等 D1–D11 全部拍板再写任何东西 | **否决** | 全部停摆；D17 的 provisional 默认建议可在不承诺的前提下把规格写完 |

## 5. 后果

### 5.1 正面

- 仓库在 Phase 0 即具备「照着开工」的文件级指引，v0.5 只需回填评审结论而非重写。
- 三个 CI + 一致性校验 + 单测构成可跑的质量底线；R-19–R-24 有自动守卫。
- 契约冻结降低后续迭代成本；历史归档只增不改（D22）。

### 5.2 负面 / 代价

- v0.4 仍**不能运行任何合成 / 训练 / 服务**；对期待「马上出声音」的评审者是落差。
- `src/**` 全是 `NotImplementedError`，静态看像「空壳」；必须用主方案 §0 诚实基线与 §3.1 完成度表配合阅读。
- 规格与签名是双份文本，存在 R-19 漂移风险 → 由 `check_consistency.py` 与单测缓解，但仍需 v0.5 人工复审。
- 新增 `Impl:` footer 与更多受保护路径，PR 流程略变重。

### 5.3 不变量（任何后续版本不得破坏）

| 不变量 | 守卫 |
| --- | --- |
| `spec_version == "0.3.0"`、顶层 `additionalProperties === false` | 单测 + `check_consistency.py` (b) |
| 错误码表唯一真源、只追加 | `check_consistency.py` (a) |
| `calibration.status == "uncalibrated"`（Phase 2 前） | `check_consistency.py` (e) |
| `registry.production == null`（Phase 0） | D18 + 人工评审 |
| `LICENSE` 为 PolyForm NC 1.0.0 官方逐字原文 | `license-check.yml` |
| 对外不称 OSI 开源 | 全库措辞 + `NOTICE` |
