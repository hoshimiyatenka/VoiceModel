# ADR-0003：参数化控制层（L5 VoiceSpec）实现路径

| 项 | 内容 |
| --- | --- |
| 状态 | **Accepted（契约层）/ Phase 3 待实现** |
| 日期 | 2026-11-04 |
| 关联 | 技术栈方案 §5 / §9、`configs/voicespec/voicespec.schema.json`、`docs/voicespec/README.md`、`docs/voicespec/ERROR-CODES.md` |
| 取代 | v0.1 §5.4 的 M1–M6 优先级（`M4>M1>M2>M5>M3>M6`） |

## 背景

「所有声音可以参数化细条」是项目第一需求（F3）。v0.1 定义了五层 VoiceSpec 与 M1–M6 控制手段；v0.2 用论文核验后把连续物理量的首选手段从 M1 改为 M2。但一直只有文字约定，没有机器可执行契约，导致三个风险：

1. 参数拼写错误被静默忽略 → 细调不可信；
2. 冲突靠口头约定，实现时容易写成静默覆盖；
3. 换基座时上层调用方要跟着改。

v0.3 需要把 L5 变成**可校验、可版本化、可测试**的正式契约。

## 决策

### 1. 契约形式：JSON Schema draft 2020-12 单一真源

- 文件：`configs/voicespec/voicespec.schema.json`，五层拆为 `$defs`（`IdentitySpec` / `ProsodySpec` / `StyleSpec` / `LinguisticSpec` / `RenderSpec`），另含候选 `AttributeSpec` 与只读 `AuditSpec`。
- **全部对象 `additionalProperties:false`**：未知字段直接 `E-SCHEMA-002`，禁止静默忽略。
- 数值范围、枚举、URI 格式、字段依赖用 Schema 静态表达（`allOf.if/then`）；跨字段算术/比较留给控制层并在错误码表登记，避免手写 if 散落。
- `spec_version` 用 `const: "0.3.0"` 锁死，版本演进规则见错误码表 §7。

### 2. 两层校验：S 层（Schema）+ C 层（Control）

```
解析 JSON → S 层（结构/类型/范围/枚举/静态依赖）→ preset 解析合并
→ C 层（语义冲突/能力探测/降级/许可/审计）→ 合成 → 门禁
```

- S 层可用标准库 `jsonschema` 直接跑（仓库提供 `scripts/validate_voicespec.py`），不依赖项目运行时；CI 对 `examples/*.json` 全量校验。
- C 层是项目自有逻辑，错误码全部登记在 `docs/voicespec/ERROR-CODES.md`，**错误码稳定、只追加不改义**。
- 响应信封统一 `valid` / `errors[]` / `warnings[]`；`/v1/synthesize` 失败 400，`/v1/presets/validate` 失败 422。

### 3. 冲突消解：显式，不静默

| 规则 | 落点 |
| --- | --- |
| `rate` ↔ `duration_*` 互斥 | Schema `ProsodySpec.not` 静态拦截 + C 层 `E-CONFLICT-001` 兜底 |
| `duration_ms` ↔ `pauses[]` | C 层校验 `Σpauses < duration_ms × 0.4`（`E-CONFLICT-002`） |
| `voice_blend` ↔ `speaker_lock=true` | C 层 `E-CONFLICT-004` |
| `emotion` ↔ `style_prompt` | 离散优先，prompt 作修饰并写审计（`W-CONFLICT-006`） |
| `scenario` ↔ 显式参数 | 显式覆盖默认值（`W-CONFLICT-007`） |
| `energy_db` ↔ `loudness_lufs`、`pitch_semitones` ↔ `pitch_contour` | **判定为不冲突**，同时生效；登记在案防止实现误加互斥 |

### 4. M1–M6 优先级（v0.2 §5.3 修正版，正式确立）

```
M4 文本确定性规则 > M2 声学特征编辑（连续量）> M1 原生条件（离散量）
> M5 参考解耦 > M3 adapter 混合 > M6 DSP（仅限渲染层/降级）
```

依据：FastSpeech 2 `arXiv:2006.04558` 证明 F0/energy/duration 可作显式条件注入，连续物理量走 M2 比自然语言指令更精确可复现；`pitch`/`rate` 主控制**禁用 M6 DSP**（金属音、损相似度），仅作降级并 `audit.degraded=true` `W-RENDER-001`。

### 5. 能力探测与降级

- `duration_mode=exact` 但基座无显式时长头 → **报错** `E-CAPABILITY-001`，不静默降级（F4 已升 P0 候选）。
- `pitch_contour` 曲线但基座不暴露中间特征 → 降级为 `native` + `pitch_range` 近似，告警 `W-CAPABILITY-002`。
- `attributes` 中任一属性未过 §5.6 单参数 5 点单调性扫描 → 拒绝该属性 `W-CAPABILITY-003`，不得进 production preset。
- `style_prompt` 作为 preset 唯一控制手段 → `E-CAPABILITY-004`。

### 6. 与许可/合规联动

- `render.watermark` 默认 `true`；无商业授权凭证时 `false` → `E-LICENSE-001`（v0.2 §2.6 + AudioSeal `arXiv:2401.17264`）。
- `ref_audio_uri` 必须指向已注册且已授权说话人 → `E-LICENSE-002`。
- 每个 preset 携带 `audit.license = PolyForm-Noncommercial-1.0.0`；`audit.*` 为服务端只读字段，客户端传入 → `E-AUDIT-001`。

### 7. 可复现性

固定 `preset@version + model@commit + seed + text + deps_lock` → 波形 byte-level 一致（Q9）。`AuditSpec` 记录 `request_id` / `model_commit` / `preset_resolved` / `gate_report` / `watermark_id` / `degraded`，全链路可追溯。

## 备选方案与否决理由

| 备选 | 否决理由 |
| --- | --- |
| Protobuf / 自定义 DSL | 需要生成代码与运行时，文档可读性差；JSON Schema 编辑器/CI 生态最成熟，且 API 本来就是 JSON |
| 只写文档约定、不落 schema | 无法防止拼写错误与静默覆盖，正是本 ADR 要解决的问题 |
| 把全部冲突塞进 JSON Schema | `Σpauses < duration_ms × 0.4` 等跨字段算术 JSON Schema 2020-12 表达不了，硬塞会牺牲可读性；分层更清晰 |
| 允许额外字段（便于前向兼容） | 与「禁止静默忽略」冲突；兼容通过 `spec_version` 显式升级解决 |

## 后果

**正面**
- 契约可机器校验、可在 CI 回归、可版本化；换基座不动上层。
- 冲突与错误码显式化，「细调」结果可信、可复现、可取证。
- S 层用标准库，零项目耦合，外部贡献者也能本地验证。

**负面 / 成本**
- `additionalProperties:false` 意味着新增参数必须走 minor/major 版本升级，不能偷偷加字段。
- C 层错误码较多（§4 共 18 个），Phase 3 实现与测试工作量不小。
- 部分约束（跨字段算术）仍依赖手写 C 层，需靠错误码表 + 单测防止漂移。
- `AttributeSpec` 仍是候选，逐属性过扫描前不得开放，避免「参数开放了但不可控」。

## 验收条件（Phase 3）

- [ ] 两个 API 接入 S+C 两层校验，错误码与本文一致
- [ ] `examples/*.json` 全部通过；故意非法用例（`rate`+`duration_mode=exact`）被拦截
- [ ] 每个开放参数完成 §5.6 单参数 5 点扫描并归档报告
- [ ] preset 注册/版本解析可用；`audit.*` 服务端填充生效
- [ ] golden_set 回归 0 异常（Q8）
