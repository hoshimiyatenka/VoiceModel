# ADR-0001：许可策略 —— 开放权重 + 非商业许可 + 商业例外

| 项 | 内容 |
| --- | --- |
| 状态 | **Proposed（待法务批准 D11 后转 Accepted）** |
| 日期 | 2026-11-04 |
| 关联 | 技术栈方案 v0.2 §2、`LICENSE`、`NOTICE`、`LICENSE-COMMERCIAL.md`、`docs/licensing/UPSTREAM-LICENSE-MATRIX.md` |
| 决策者 | 项目方（版权持有人）；复核：法务（待） |

## 背景

用户指令（第二轮 #1）：「这个声音模型是开源的 但是保留一定权力 例如使用此模型的人 不得商业化」。

需要一个既「公开可得」又「禁止商业化」，且**保留项目方单独授权商用权利**的许可结构。同时本项目基于第三方开源 TTS 基座微调，必须处理上游许可证传导。

## 备选方案

| 方案 | 优点 | 否决理由 |
| --- | --- | --- |
| A. Apache-2.0 / MIT，靠商标与服务条款限制商用 | OSI 认证「开源」 | **OSI OSD 第 6 条禁止按用途领域歧视，Apache/MIT 明确允许商用**，无法禁止商业化；商标只能防冒名，不能防使用 |
| B. GPL / AGPL | 强 copyleft、有专利条款 | **GPL 允许商用与收费**，copyleft 不禁止商业化；达不到目的 |
| C. CC BY-NC 4.0 | 熟悉的 NC 条款 | 为「作品/素材」设计，非软件/模型；无明确专利授权；不如为软件设计的 PolyForm 精确 |
| D. CC BY-NC-SA 4.0 权重（如 Spark-TTS）+ 沿用 | 天然禁商用 | **SA 传染**：衍生作品须同许可，项目方不能改用自有 NC 条款或自定义商业例外；双授权变现路径受阻（见下） |
| E. 自定义 NC 许可 | 完全贴合需求 | 起草与法务成本最高，且缺乏社区认知度 |
| **F. PolyForm Noncommercial 1.0.0 + 双授权** | 为软件/模型设计、条款简短、含专利授权、**无 SA 不传染**、明确允许 licensor 另行授权 | 需接受「非 OSI 开源」的对外表述 |

## 决策

1. **对外表述**：称「**开放权重 / 源码可得（source-available, open-weight）**」，**不称 OSI 认证 Open Source**。原因：OSI OSD 第 6 条 "No Discrimination Against Fields of Endeavor" 与「禁止商业化」不可兼得；自称开源会造成条款自相矛盾。
2. **公众许可**：`LICENSE` 采用 [PolyForm Noncommercial License 1.0.0](https://polyformproject.org/licenses/noncommercial/1.0.0) **官方原文逐字**（核验日期 2026-11-04，取自官方 `.txt` 纯文本），不修改一字。
   - 允许：任何非商业目的；个人研究/实验/测试/学习/娱乐/爱好（无预期商业应用）；非商业组织（慈善/教育/公共研究/公共安全与健康/环保/政府机构，无论资金来源）；法律合理使用。
   - 不含：任何以商业优势或金钱报酬为主要目的的用途、企业内部运营、Hosted/API 语音生成服务、间接产生收入的用途。
3. **项目特定信息**全部放 `NOTICE`（含 `Required Notice:` 行、上游归因、覆盖边界、使用限制），不放进 `LICENSE`，避免破坏官方许可文本有效性。
4. **权利保留 / 双授权**：`LICENSE-COMMERCIAL.md` 建立商业授权申请通道；版权持有人保留向特定主体单独授予商业许可的权利。依据 PolyForm NC `No Other Rights` 原文：*"these terms do not ... prevent the licensor from granting licenses to anyone else"*。
5. **上游基座**：优先选**宽松许可权重**（Apache-2.0），候选 `CosyVoice 2` / `Qwen3-TTS` / `VoxCPM2`（Phase 2 实测定型）。**不使用 `Spark-TTS` 权重作发布基座**（CC-BY-NC-SA-4.0），仅参考其属性级控制论文 `arXiv:2503.01710`。
6. **覆盖边界**：NC 条款只覆盖本项目自有增量（代码、VoiceSpec 契约、preset、词典、标注、golden_set、LoRA/adapter/微调权重、模型卡、文档、音色资产）；上游原权重依其自身许可，第三方仍可按 Apache-2.0 使用，项目方不主张限制。依据 Apache-2.0 §4 可对修改与衍生作品整体附加不同条款，但须保留上游归因且不得剥夺第三方对上游原作的权利。
7. **技术侧强化**（不可替代许可证）：AudioSeal 水印（`arXiv:2401.17264`, MIT）默认开启；模型卡 `license` 字段；`NOTICE` 随分发保留；音色注册鉴权；审计日志；商业版单独分发。

## 后果

**正面**
- 满足「公开可得 + 禁止商业化 + 保留项目方权利」三项原始诉求。
- 双授权保留未来变现路径。
- 宽松许可基座使合规清晰，NC 只覆盖自有资产，权利范围不被夸大。
- 无 SA 传染，衍生许可选择权留在项目方。

**负面 / 成本**
- 不能自称 OSI 开源，社区传播需解释术语（README 需写明）。
- 上游原权重可被第三方按 Apache-2.0 商用，NC 无法覆盖——这是硬边界，需在 README 明示。
- 法务工作不可省：商业化边界 FAQ、书面协议模板、`NOTICE` 归因清单、D11 签字。
- `IndexTTS2`（bilibili 许可）与 Fish Audio 的自定义条款若被采用，需额外法务确认。
- 许可一经分发即对已分发副本生效，**发布权重前必须完成法务批准**（P0 阻塞）。

## 触发复核的条件

- 用户要求改为 OSI 认证开源（方向性变更，需重新评审「禁止商业化」是否放弃）。
- 上游基座更换或新增依赖（须更新许可证矩阵与 `NOTICE`）。
- PolyForm 发布新版本且法务建议升级。
- 出现首个商业授权申请（检验双授权流程）。
